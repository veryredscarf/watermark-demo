## EXP-012：模拟登录图片水印与浏览器原图自检

- 日期：2026-11-18（Asia/Shanghai）；关联 R-02、R-08、R-13、R-17、ADR-015；工作分支 `feat/login-watermark-image`，起点提交 `7d4e4d4`，本次已验证功能提交 `80dacbf0d925f45c21318b2e7bf4e347d5bf3718`。

- 环境：Windows、Node.js 24.22.3、Chrome 154.0.8037.92、Vite 7.3.7；虚构身份“青禾”，默认浅色页面，1280×720 启动窗口，页面缩放 100%，实验图块 160×160，暗图案 opacity 0.05。浏览器经本地 4173/5173 接口访问，无真实业务或平台文件。
- 固定样本清单：[tests/fixtures/README.md](../tests/fixtures/README.md)，SHA-256 `9FC56BA259D0AEFE7CC0D3EAD3497BD77DA18821B3DE201005F1E3C8CB818266`；完整图和区域图的逐文件散列、尺寸、真值见清单。样本为虚构演示页，不能计入正式 T1/T1-C。
- 复现与命令：`node --test apps/api/tests/api.test.mjs packages/watermark-core/tests/extract.test.mjs`；`vue-tsc --noEmit -p apps/web/tsconfig.json`；从 `apps/web` 运行 `vite build --configLoader native`；`node scripts/browser-smoke.mjs`。后者自动启动本地 API/Vite/Chrome，登录、截图、上传至页面试验台，并复验两张固定样本；输出含浏览器版本、当前标识、逐图分数和匹配位数。
- 首次失败：服务端图块已加载，但完整浏览器截图被判为“未检出”，一次记录为分数 31.48、匹配位 15/64。原因是提取器仅按平均亮度差选同步位置，页面大字的错误位置分数高于真实图块。先只改候选排序为“匹配位数优先、分数次之”；同样的浏览器截图流程改为 64/64 匹配。随后单独把暗图案 opacity 从 0.12 降到 0.05，重新执行浏览器流程仍匹配。同类页面的虚构截图及 640×360 区域图纳入固定回归；首次失败图未留存，不将它误写成固定样本。
- 最终动态样本观察：一次运行中服务端标识 `49e350bb53366479`，完整截图提取 `49e350bb53366479`、64/64、分数 11.93；同次 `(600,0)` 的 640×360 区域图提取同值、64/64、分数 11.93。后续重跑动态租约 `0dce71b3a3c5257e` 的完整图和区域图仍分别 64/64；两张固定样本均恢复 `49e350bb53366479`，脚本退出码 0。

- 结论：当前实验图块与试验台的单次浏览器原图闭环可复现；仅验证当前租约辅助同步的少量虚构样本。R-14 的至少 1000 张独立原图 100% 门槛、R-15 的两次非原图链路及 R-16 真实业务接入均未通过，不能据此宣称上线可用。
