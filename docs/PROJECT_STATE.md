## 已确认范围与当前实现

- 用户最新确认：首版仅覆盖运行中的系统页面；Excel、PDF 和其他导出文件暂不处理。真实目标是全部列表页，但当前没有业务系统源码和路由清单，R-16 未开始实装。
- 用户授权本轮先实现：模拟登录时 Node.js 根据虚构身份签发当前明暗标识，返回一张 SVG 水印图片；Vue 3 只平铺渲染该图片；试验台展示服务端原图块，并对上传的页面截图显示是否提取到当前 64 位标识。对应 R-02、R-13、R-17、ADR-015。
- 实验图块为 160×160 像素，可见文案加 64 位像素对，暗图案 opacity 0.05；水印图片和 96 位可见码、64 位标识关联到同一租约。算法版本 `lab-pair-1` 是开发向量，没有纠错、独立盲提取或抗平台重压缩的已验证能力。
- 暂定输入下限为宽至少 640 且高至少 360 像素，任一边更小即返回证据不足。达到尺寸仍须有足够图案，不保证任意区域成功；这不是 A→B→C 两次非原图转发的支持下限。
- Node.js 内置 SQLite 持久化租约映射和审计，默认文件位于 Git 忽略的 `artifacts/runtime/`；演示用户在代码中，演示会话仍在内存。真实身份、迁移、备份和生产运维未完成。
- 既有 `chore/repository-baseline` 是未验收基线，本轮代码位于独立功能分支。先前出现的来源不明 `watermarkNew.zip` 未纳入本轮改动或暂存。
