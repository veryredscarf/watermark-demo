# 水印识别实验与验收协议（待审阅）

版本：0.1 提案；2026-11-03。此处均为未来验收目标，当前没有暗水印实验结果。任何“通过”结论必须链接到 EXP 编号、样本清单版本、代码提交和逐图输出。

## 1. 样本与真值

每张样本有唯一 sampleId；清单至少记录 leaseId 的脱敏引用、预期暗码、页面模板、明暗主题、视口、操作系统、截图方式、平台与客户端版本、B/C 设备系统、处理阶段、裁剪坐标、最终宽高、文件 SHA-256、生成时间、数据分组。真值来自服务端签发记录，不能通过观察图片或 OCR 反推后填入。

样本分为调参集、固定回归集、封存验收集。按访问租约和源截图整体分组，同一原图的不同压缩版本只进入同一组，防止数据泄漏。封存集在阈值、图块参数和模型版本冻结后才运行；失败后修改方案必须换新的封存批次，旧批次仍保留作历史回归。小型虚构样本可入 Git；真实业务图、社交平台最终文件和模型权重放受控存储，Git 只保存清单、散列及必要的脱敏指标。

## 2. 分层场景

| 层级 | 输入文件 | 目的与门槛 |
| --- | --- | --- |
| T0 | 确定性码字和图块向量 | 编码、解码、版本兼容与错误纠正完全符合固定向量；失败时不进入截图实验 |
| T1 | A 电脑直接保存的原始截图 | 固定验收集至少 1000 张，暗码完全正确 100%，错误归属 0；失败立即阻断后续层级 |
| T2 | A 从电脑非原图发送，B 保存收到的图片 | 微信与企业微信分别记录；不得用 A 的本地文件替代 B 的实际文件 |
| T3 | B 在手机普通保存 T2 图片，再非原图发送，C 保存最终图片 | 用户指定的上线硬门槛；以 C 保存的文件为唯一识别输入 |
| T4 | A 在第一次发送前按预登记坐标裁剪约 50% 面积，再走 T3 同一链路 | 与完整图分开统计；裁剪坐标与最终尺寸均记录 |

T1 覆盖 1366×768、1920×1080，文字、表格、图表、图片、弹窗、长页面，以及明暗主题。T3 完整图和 T4 预登记裁剪图分别统计；每层均为微信/企业微信 × B 的 Android/iOS × C 的 Android/iOS，共 8 个格子。每格至少 200 张不同租约与源截图，两层至少 3200 张最终文件；T3 与 T4 不得互相凑数。A 初期采用 Windows 桌面；Mac 或其他系统加入前另行建立格子。若平台在既定操作中将图片缩小到不可识别，不从分母剔除，记为失败。T2 保留逐格结果以定位第一次压缩的损失，但不能替代 T3 验收。

操作脚本需固定：A 对已加载水印的页面使用系统截图、保存本地原图、以非原图发送；B 在对应手机上从聊天接收并普通保存，不请求原图，再从相册以非原图发给 C；C 保存收到的文件并交给提取程序。截图、聊天选择和保存步骤留有操作记录，禁止用本地 JPEG 重压缩模拟真实平台链路并冒充 T3 结果。

## 3. 指标与门槛

主指标是暗码完全正确恢复率，分母为所有符合预先登记操作步骤的样本；未检出、证据不足和错误码都算未恢复。T3 和 T4 每个格子的实测完全正确率目标不低于 95%（至少 200 张时，至少 190 张完全正确）。逐格报告正确数/总数及预先指定的 Wilson 95% 区间；发布判定使用预登记的样本比例门槛，样本通过不等于总体成功率保证。任何错误地关联到其他租约/用户的结果都是错误归属，发布验收要求 0 次。另以至少 10000 张无水印、其他租户和不同图片内容的负样本测试，要求观察到 0 次错误归属；这不意味着真实风险为零。

同时报告逐图检测分数、同步成功率、纠错前位错误率、未检出率、证据不足率、误归属率、提取耗时和峰值内存。视觉质量在同一页面同一状态下比较有/无暗水印截图，SSIM 目标不低于 0.995，并进行人工可读性检查。视觉门槛与恢复率冲突时，不私自放宽任何一方，提交 ADR 供审阅。

阈值在调参集上确定，并在封存集运行前冻结。系统不能以“最高分候选”强行归属；达不到匹配条件时输出证据不足或未检出。可见码 OCR 和人工核验单独计数，不补入暗码成功率。

## 4. 每次实验的最小记录

每个 EXP 条目写明：可证伪假设、唯一主要变量、固定条件、代码提交、算法与密钥版本、样本清单 SHA-256、运行命令、环境与随机种子、前后逐图输出、分层指标、失败样本、结论和下一步。结果文件采用机器可读格式，报告脚本从逐图结果生成汇总表。不得只记录总体成功率或“测试正常”。

新算法或参数晋级必须同时满足：T0/T1 不退化；历史失败样本不回退；负样本无错误归属；视觉和性能在门槛内；目标场景在同一固定集上优于基线，并在封存集上成立。失败结果保留，不删除样本、不改真值、不事后改变分母。每次修复把原失败样本加入固定回归集。

## 5. 自动化与发布

每次提交运行编解码向量、较小的固定原图与负样本集、类型检查和接口测试；候选版本运行完整 T1–T4 与 10000 负样本。真实社交平台样本若不能自动采集，使用受控人工采集与双人核对操作记录。发布记录列明支持的平台、版本、设备、页面和图片范围；未测渠道标为未验证。

本协议依赖 AGENTS.md、DEVELOPMENT_WORKFLOW.md 和 PROJECT_STATE.md 的事实/推测/待确认分离规则。聊天记忆不能替代实验记录。

NIST 软件开发验证建议强调自动化与历史用例（https://csrc.nist.gov/pubs/ir/8397/final）；DVC 实验管理文档说明代码、数据、参数、指标和结果的关联方式（https://doc.dvc.org/user-guide/experiment-management）。本项目先使用 Git 提交、SHA-256 样本清单与逐图结果建立可复现链路；需要大规模模型或数据时再评估 DVC，不将工具本身当作质量保证。
