# 水印识别实验与验收协议（待审阅）

版本：0.2 提案；2026-11-03。此处均为未来验收目标，当前没有暗水印实验结果。任何“通过”结论必须链接到 EXP 编号、样本清单版本、代码提交和逐图输出。

## 1. 样本与真值

每张样本有唯一 sampleId；清单至少记录 leaseId 的脱敏引用、预期暗码、页面模板、明暗主题、视口、操作系统、截图方式、平台与客户端版本、B/C 设备系统、处理阶段、截图方法、裁剪坐标、裁剪前后宽高、长宽比、占受保护视口面积比例、文件 SHA-256、生成时间、数据分组。真值来自服务端签发记录，不能通过观察图片或 OCR 反推后填入。

样本分为调参集、固定回归集、封存验收集。按访问租约和源截图整体分组，同一原图的不同压缩版本只进入同一组，防止数据泄漏。封存集在阈值、图块参数和模型版本冻结后才运行；失败后修改方案必须换新的封存批次，旧批次仍保留作历史回归。小型虚构样本可入 Git；真实业务图、社交平台最终文件和模型权重放受控存储，Git 只保存清单、散列及必要的脱敏指标。

## 2. 分层场景

| 层级 | 输入文件 | 目的与门槛 |
| --- | --- | --- |
| T0 | 确定性码字和图块向量 | 编码、解码、版本兼容与错误纠正完全符合固定向量；失败时不进入截图实验 |
| T1 | A 电脑直接保存的完整原始截图 | 固定验收集至少 1000 张，暗码完全正确 100%，错误归属 0；失败立即阻断所有后续层级 |
| T1-C | A 电脑原生区域截图或从 T1 文件无重采样裁剪的本地图片 | 每个拟声明支持的裁剪档先用至少 200 张不同租约固定样本验证暗码完全正确 100%、错误归属 0；未通过的档位不进入该档的平台验收 |
| T2 | A 从电脑非原图发送，B 保存收到的图片 | 微信与企业微信分别记录；不得用 A 的本地文件替代 B 的实际文件 |
| T3 | B 在手机普通保存 T2 图片，再非原图发送，C 保存最终图片 | 用户指定的上线硬门槛；以 C 保存的文件为唯一识别输入 |
| T4 | A 直接截取不同尺寸的页面区域，或在第一次发送前对 T1 图片裁剪，再走 T3 同一链路 | 按裁剪档、截图方法、形状和位置与完整图分别统计；记录原始与最终像素尺寸，不以约 50% 面积代表所有裁剪 |

目标管理页面先用虚构数据验证页模拟其布局；在实际系统源码或正式接入点不可用时，所有结果仅能标为 SDK/模拟页实验，不能作为 R-16 真实系统验收。表格数据行和查询字段的小范围裁剪单独记录最小尺寸与恢复结果，未通过时不得宣称该类局部截图可恢复。

T1 开始前先完成 LOCAL_STORAGE_PLAN.md 的签发持久化与强制重启核验：同一明暗码在服务重启后仍能查回同一租约，数据库写入失败不得返回高敏感内容。T0 的纯向量测试可不依赖数据库。

T1 覆盖 1366×768、1920×1080，文字、表格、图表、图片、弹窗、长页面，以及明暗主题。T3 完整图与每个拟声明支持的 T4 裁剪档分别统计；每档均为微信/企业微信 × B 的 Android/iOS × C 的 Android/iOS，共 8 个格子。每格至少 200 张不同租约与源截图；完整图至少 1600 张，每增加一个声明支持的裁剪档再增加至少 1600 张最终文件，各档不得互相凑数。A 初期采用 Windows 桌面；Mac 或其他系统加入前另行建立格子。若平台在既定操作中将图片缩小到不可识别，不从分母剔除，记为失败。T2 保留逐格结果以定位第一次压缩的损失，但不能替代 T3 验收。

操作脚本需固定：A 对已加载水印的页面使用系统截图、保存本地原图、以非原图发送；B 在对应手机上从聊天接收并普通保存，不请求原图，再从相册以非原图发给 C；C 保存收到的文件并交给提取程序。截图、聊天选择和保存步骤留有操作记录，禁止用本地 JPEG 重压缩模拟真实平台链路并冒充 T3 结果。

## 2.1 变尺寸截图与裁剪档（R-17）

截图可能由系统截图工具直接选区，也可能截全屏后再裁剪；两种路径分别采集，不以固定浏览器分辨率代替最终图片尺寸。每张样本记录原生选区/事后裁剪、来源视口与 DPR、选区坐标、最终宽高、长宽比、占受保护视口面积比例、页面区域、可见完整码数和预期保留的暗图块范围。窄条、单行表格、查询区、操作区、表格边缘、中心和弹窗分别预登记；没有足够水印信息的有效选区仍计入对应档位的失败分母。

以受保护视口面积为基准，先建立 C1（50%–不足 100%）、C2（25%–不足 50%）、C3（10%–不足 25%）、C4（不足 10%，含单行或窄条）四档；完整图为 C0。面积比例之外，试采集 960×540、640×360、320×180 及长条形窗口，记录实际像素和平台处理后的变化。这些是实验分组，不是已支持的最小尺寸。C4 默认只做探索；任何档位都须先通过 T1-C，再逐格通过 T4，才能写入发布支持范围。若像素尺寸、保留图块或平台缩放使信息不足，正确结果为证据不足/未检出，不得强行归属。

四张用户授权的列表页截图仅用于设计采样位置和模拟页布局，见 [参考图清单](assets/reference-list-pages/README.md)。它们没有本项目签发的水印，不能计入 T0–T4 的任何成功或失败样本；真实系统所有列表路由仍需单独盘点。

## 3. 指标与门槛

主指标是暗码完全正确恢复率，分母为所有符合预先登记操作步骤的样本；未检出、证据不足和错误码都算未恢复。T3 完整图与每个声明支持的 T4 裁剪档逐格实测完全正确率目标不低于 95%（至少 200 张时，至少 190 张完全正确）。未声明支持的档位只报告探索结果，不并入通过档位的分母。逐格报告正确数/总数及预先指定的 Wilson 95% 区间；发布判定使用预登记的样本比例门槛，样本通过不等于总体成功率保证。任何错误地关联到其他租约/用户的结果都是错误归属，发布验收要求 0 次。另以至少 10000 张无水印、其他租户和不同图片内容的负样本测试，要求观察到 0 次错误归属；这不意味着真实风险为零。

同时报告逐图检测分数、同步成功率、纠错前位错误率、未检出率、证据不足率、误归属率、提取耗时和峰值内存。视觉质量在同一页面同一状态下比较有/无暗水印截图，SSIM 目标不低于 0.995，并进行人工可读性检查。视觉门槛与恢复率冲突时，不私自放宽任何一方，提交 ADR 供审阅。

阈值在调参集上确定，并在封存集运行前冻结。系统不能以“最高分候选”强行归属；达不到匹配条件时输出证据不足或未检出。可见码 OCR 和人工核验单独计数，不补入暗码成功率。

## 4. 每次实验的最小记录

每个 EXP 条目写明：可证伪假设、唯一主要变量、固定条件、代码提交、算法与密钥版本、样本清单 SHA-256、运行命令、环境与随机种子、前后逐图输出、分层指标、失败样本、结论和下一步。结果文件采用机器可读格式，报告脚本从逐图结果生成汇总表。不得只记录总体成功率或“测试正常”。

新算法或参数晋级必须同时满足：T0/T1 不退化；历史失败样本不回退；负样本无错误归属；视觉和性能在门槛内；目标场景在同一固定集上优于基线，并在封存集上成立。失败结果保留，不删除样本、不改真值、不事后改变分母。每次修复把原失败样本加入固定回归集。

## 5. 自动化与发布

每次提交运行编解码向量、较小的固定原图与负样本集、类型检查和接口测试；候选版本运行完整 T1–T4 与 10000 负样本。真实社交平台样本若不能自动采集，使用受控人工采集与双人核对操作记录。发布记录列明支持的平台、版本、设备、页面和图片范围；未测渠道标为未验证。

本协议依赖 AGENTS.md、DEVELOPMENT_WORKFLOW.md 和 PROJECT_STATE.md 的事实/推测/待确认分离规则。聊天记忆不能替代实验记录。
