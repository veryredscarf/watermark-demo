# 需求与验收基线

版本：0.2（暗水印部分待用户审阅）。`P0` 是首版必须完成，`P1` 为首版后扩展。下列阈值是实验目标，在真实页面基线测量后可通过决策记录调整。

## 角色与使用流程

- 员工：登录受保护业务系统，查看带水印的数据页面；正常交互、复制允许的内容、打印受控页面。
- 系统管理员：配置页面/数据级别、文案、开关和故障策略；不能任意查看调查映射。
- 安全调查员：凭授权查询追溯码，保全泄露样本，核对审计日志并形成报告。
- 审计员：查看策略和调查操作历史。

## 功能需求

| ID | 优先级 | 要求 | 可核验的验收标准 |
| --- | --- | --- | --- |
| R-01 | P0 | 受保护访问签发 | 服务端先认证、鉴权，再为租户/用户/资源/访问实例签发唯一追溯码；未授权请求不签发 |
| R-02 | P0 | 可见平铺水印 | 页面各主要区域显示批准文案、时间与追溯码；在 1366×768 视口按四角和中心各截取 50% 宽、50% 高区域的五张样本中，每张至少保留一个完整码；其他裁剪样本另行记录 |
| R-03 | P0 | 生命周期 | 初始化、资源切换、用户切换、续期、退出登录及组件卸载后，显示内容与当前有效访问一致；无重复叠层和定时器泄漏 |
| R-04 | P0 | 交互和可访问性 | 水印不拦截点击/滚动/选择，不进入焦点顺序或屏幕阅读器正文；在 200% 缩放和关键弹窗场景仍可完成业务任务 |
| R-05 | P0 | 核验 | 有权限者输入码可查看唯一签发记录；内部审计可区分无效码、跨租户查询、无权限和格式错误，对外响应不泄露其他租户是否存在该码；每次查询留审计记录 |
| R-06 | P0 | 故障策略 | 高敏感页在签发不可用或失败时，服务端不返回敏感内容；前端显示清晰错误与重试入口；恢复后可正常进入 |
| R-07 | P0 | 打印 | 对首批指定页面，打印/PDF 样本含可读追溯码；若浏览器打印能力不能满足，改为服务端生成受控文件并记录业务限制 |
| R-08 | P0 | 审计与保全 | 签发、访问、核验、策略修改与调查操作可关联；记录不含密钥、访问令牌或敏感正文；保留期和访问角色可配置 |
| R-09 | P0 | SDK 接入 | 提供初始化、更新、销毁 API 和框架无关接入说明；重复初始化与异常卸载不破坏原页面 |
| R-10 | P1 | 下载/导出物 | 指定 PDF、图片、报表在生成链路加入独立追溯信息并经对应样本验证 |
| R-11 | P1 | 多业务策略 | 按租户、资源分级和业务线配置文案、密度、灰度和失败策略；策略变更有审计 |
| R-12 | P0 | 调查辅助 | 受权调查员可上传泄露样本；保存文件散列、案件号、来源、操作者、算法版本与判断依据；权限与保留期限在生产接入前定案 |
| R-13 | P0 | 暗水印签发与绘制 | 服务端为每次授权访问签发与可见码映射的独立暗码；Vue 3 页面平铺不拦截交互的图块；无密钥进入前端，明暗主题和主要页面完成视觉检查 |
| R-14 | P0 | 原图提取硬门槛 | 在 BENCHMARK_PROTOCOL.md 固定的至少 1000 张 A 本地原始截图中，暗码完全正确 100%、错误归属 0；未通过则停止更高层级验收 |
| R-15 | P0 | 两次非原图转发提取 | A 电脑非原图发 B、B 手机普通保存并非原图发 C；以 C 保存的最终文件验收，微信和企业微信各矩阵格子至少 200 张，完全正确率不低于 95%、错误归属 0；失败不得宣称支持 |
| R-16 | P0 | 真实业务系统接入 | 在用户提供截图所示类型的实际 Vue 3 管理页面接入，而非仅处理截图文件；查询区、操作区、表格、分页及弹窗的数据区域均按策略覆盖；逐项验证交互、可读性、滚动、缩放与 T1 原图提取，结果记录在真实系统授权测试环境中。当前只能交付可接入 SDK 和虚构数据验证页，不能据此标记 R-16 已通过 |

## 非功能约束

| ID | 维度 | 首版基线 |
| --- | --- | --- |
| N-01 | 安全 | 全链路 HTTPS；签发和核验需鉴权；密钥只在服务端；追溯码随机且不可从码本身推断身份；限流、防枚举、租户隔离 |
| N-02 | 隐私 | 默认仅显示批准的短身份文案；原始用户标识留在受控服务端映射；不用浏览器永久存储追溯码；留存期由企业策略确定 |
| N-03 | 性能 | 在目标页面对照测量：20 次同条件加载中，水印初始化增加的脚本执行时间 P95 不超过 50 ms；布局更新不产生持续长任务；实际阈值经 S1 基线复核 |
| N-04 | 可用性 | 目标浏览器与版本由接入系统列明；最低覆盖桌面 Chromium 系列及 Firefox 的现行企业支持版本，具体版本在 S0 锁定 |
| N-05 | 可观测性 | 监控签发失败率、渲染异常率、核验请求、策略版本、故障模式；日志中不记录敏感正文和原始会话凭证 |
| N-06 | 可维护性 | SDK 有类型定义、示例、版本策略和销毁语义；服务接口有版本号、错误码和兼容期 |
| N-07 | 防误归属 | 至少 10000 张负样本观察到 0 次错误归属；低置信度、多候选或纠错失败必须返回证据不足/未检出，不自动定责 |

## 验收矩阵与测试数据

- 页面：长列表、表格、图表、图片、弹窗、全屏组件、深色/浅色主题、不同层级 iframe。
- 视口：至少 1366×768、1920×1080、移动窄屏基线；缩放 100%、200%；滚动顶部/中部/底部。
- 身份：正常、切换用户、退出、并发会话、权限撤销、租户切换。
- 网络：签发超时、401/403、429、5xx、断网、恢复、服务端时间变化。
- 对抗：删除叠层、覆盖 CSS、修改可见文字、截取局部、压缩与模糊截图；记录可恢复率与误判率，不用“绝对防篡改”做验收。
- 调查：有效码、随机码、格式错误、跨租户码、过期码、重复查询、越权查询。

暗水印详细分层、样本划分、指标与发布门槛见 BENCHMARK_PROTOCOL.md。测试样本应使用虚构身份和非生产数据。真实业务验收由业务方提供授权的测试环境与样本。

## 尚需业务确认

首批页面与数据分级；可见文案是否出现实名/工号；允许打印和下载的业务规则；目标浏览器清单；日志留存期限；调查权限和复核制度。未确认项保留在 `PROJECT_STATE.md`，不得被实现代码中的默认值悄悄固化为生产政策。
