# 明暗水印与截图溯源技术方案（待审阅）

版本：0.4 提案；2026-11-03。本文是目标设计，不表示暗水印已实现或通过测试。用户确认本方案与验收协议前，不继续编写功能代码。

## 1. 目标、边界与顺序

目标是从泄露图片中恢复服务端签发的水印标识，并据此查询访问记录。不能从有损压缩图无损重建原始截图，也不能仅凭水印自动认定泄露责任。首批受测渠道是微信和企业微信；其他平台逐一验证后才能声明支持。截图可只保留列表页中的任意区域；可恢复的最小面积、像素尺寸与形状只能在实验后按档位声明，不能保证所有小图。

研发顺序固定为：编解码固定向量 → A 电脑本地完整原始截图 → 原生区域截图与本地裁剪原图 → A 非原图发给 B → B 手机普通保存后非原图发给 C；完整图与各裁剪档分别验证。完整原图门槛未达时停止全部后续实验；某裁剪档本地原图失败时只阻断该档的平台验收。直接截图的“原图”指 A 截图后、上传社交平台前的文件，不要求它覆盖完整浏览器视口。

## 2. 访问、签发与显示

受保护业务接口先认证与资源授权，再在同一次服务端处理里创建访问事件和水印租约；高敏感数据在签发失败时不得返回。每个租约包含 96 位随机可见码与独立的 64 位随机暗码，二者映射到同一租约和租户、主体、资源、时间、策略版本。T0 纯向量实验可在内存中检查码冲突；首个服务端签发版本由本地数据库唯一约束和授权查询兜底。原始身份、会话凭据与生成密钥均不进入水印图案或普通日志。

Vue 3 适配层在受保护视口上绘制不拦截交互的可见文字层，以及平铺 Canvas 暗水印层。暗水印的候选基线为：服务端把 64 位暗码编码为 BCH(127,64) 码字；用服务端密钥和算法版本生成带同步定位图案的 256×256 像素伪随机灰度图块；前端重复合成图块。1.5%–3% 透明度仅是实验起始搜索范围，不是已证实的发布参数。明暗主题分别测量可读性与恢复率，必要时使用不同图块变体。服务端向浏览器提供当前租约的图块数据，不提供密钥；客户端可被控制，图块可被提取或移除，这是威胁模型中的剩余风险。

现有 256×256 图块对较小或狭长选区可能只留下部分同步/码字信息，不能据此承诺极小图恢复。先在 T1-C 对不同选区尺寸、位置和长宽比测量信号保留量；若失败，在固定视觉门槛下单变量比较重叠平铺、同步冗余和图块尺度等候选，并记录最小可恢复区域及失败边界，之后才进入对应裁剪档的真实转发实验。

可见码与暗码作为两条独立识别通道统计。可见码 OCR 或人工读出成功，不计入暗码恢复成功。

## 3. 图片提取与结果语义

受权调查员提交案件号与 C 收到的最终图片。Node.js 服务校验调查权限、租户、格式和大小，计算原文件 SHA-256 并留审计；图片解码后依次做尺寸与色彩归一化、图块同步、相关性检测、码字软/硬判决、纠错、租约查询。阈值只在调参集确定，封存验收集不能参与调参。

接口只返回三类结果：成功匹配、证据不足、未检出。未检出表示图案同步或检测未达到预登记阈值；证据不足表示存在候选信号，但纠错失败、出现多个候选、无法唯一映射或未满足匹配阈值。成功匹配必须同时满足同步与检测阈值、纠错有效、暗码在授权范围内唯一映射，且调查权限允许；不得“选最高分”强行归属。返回检测分数、算法版本、样本散列、查询编号和必要的签发事实；不返回密钥或无权限租户的信息。上传文件的保管期限和调查访问权限在生产接入前由企业决定。

对原图失败先逐段定位：签发与码字 → 图块像素 → Canvas 合成 → 浏览器截图 → 同步 → 纠错 → 租约查询。原图问题复现和修复前，不通过放宽阈值或训练更复杂模型掩盖。若候选基线在真实转发链路达不到门槛，先记录失败分布，再单变量调整同步、强度、图块尺度或纠错；传统方法充分比较后，才考虑离线训练模型、导出 ONNX 并由 Node.js 推理。每次路线变化写 ADR，不把研究结果预写成已验证能力。

## 4. 接口与存储变更草案

现有受保护内容响应增加可选 covert 对象：算法版本、当前租约的图块数据、尺寸与绘制策略。图块由服务端生成或经同源鉴权接口取得；不使用带访问凭据的 URL。T0 纯编解码向量可只用内存和固定真值清单；进入 T1 服务端签发与原图闭环前，Node.js 服务即需在本机 SQLite 文件中持久化租约、可见码、暗码、访问事件、算法版本和审计记录，并通过重启恢复测试。生产存储引擎按部署拓扑另行定案。数据访问层可替换，但 HTTP/JSON 契约和历史核验语义必须稳定。

新增受权图片提取接口 POST /api/watermark/v1/extractions，输入 multipart/form-data 的 caseId 与 image；输出 status（matched / uncertain / not_detected）、detectionScore、evidenceId、requestId，只有 matched 才带最小化 match 对象。confidence 是可选字段，仅在独立固定校准集完成标定后提供；标定前的 detectionScore 只是原始分数，不得称为概率。沿用现有 POST /api/watermark/v1/verify 处理手工输入的可见码。

## 5. 发布边界

暗水印只对 BENCHMARK_PROTOCOL.md 中实际通过的页面、设备、图片范围和渠道版本声明支持。原图测试、负样本误归属、视觉质量或 A→B→C 两次非原图链路任一硬门槛失败，暗水印能力不发布；可见水印如单独发布，需独立说明其范围和局限。报告保留 L0–L3 证据等级，匹配结果只构成调查线索。
## 6. 研究依据与可迁移性限制

ScreenMark 研究了任意屏幕内容截图水印的鲁棒性（https://ojs.aaai.org/index.php/AAAI/article/view/34825）；重复 JPEG 压缩研究说明社交平台多轮处理会改变嵌入信号（https://www.sciencedirect.com/science/article/pii/S0165168420300013）。这些工作支持实验方向，不证明本项目图块方案或微信/企业微信 A→B→C 链路已经达标。最终结论以本仓库的真实样本和封存验收结果为准。
