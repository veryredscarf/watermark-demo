# 全栈技术方案审查（待审阅）

日期：2026-11-05。审查基线：`98625c9`，分支 `chore/repository-baseline`。范围包括需求、架构、接口、暗水印研究、实验协议、SDK 接入、本地存储方案和 S1 演示代码。本文件是设计审查意见，不是漏洞利用证明，也不表示暗水印已实现或实验通过。以下 P0 表示在相应能力发布前必须补齐；P1 表示实施前需要明确，但不阻断纯虚构数据的研究实验。

## 已有合理基础

服务端负责签发与授权，客户端仅负责显示；可见码与暗码分别统计；T1 原图失败会阻断真实转发验收；匹配仅为调查线索；用户无法提供目标系统源码时 R-16 保持未完成。这些边界应保留。

## P0：发布前必须解决

### F-01 内容出口覆盖与发布范围不一致

`REQUIREMENTS.md` 将下载/导出列为 R-10 P1，而 `PROJECT_PLAN.md` 将页面双水印列为 P0。目标页面存在“导出”等操作；直接 API、打印、导出可能得到没有页面叠层的数据。方案虽承认每条内容路径独立保护，但尚无业务接口清单和逐出口验收。若首批页面开放这些出口，单靠 SDK 上线会形成绕过路径。

处理：在真实系统接入前列出页面、API、导出、打印、缓存、历史页面的敏感内容出口；每条路径明确服务端授权、签发/审计、产物水印或业务禁用策略。首版若保留导出，提升对应要求为 P0；否则在发布范围中明确禁用并做绕过测试。每次请求均需资源级授权。

### F-02 SDK 无法单独实现可信门禁，真实系统集成点仍未知

`TARGET_SYSTEM_INTEGRATION.md` 已如实说明目前只有截图、没有源码。SDK 的 `mount/update/destroy` 不能控制业务接口何时返回敏感数据，也不能证明业务后端对所有路径完成了签发门禁。当前 `apps/api/server.mjs` 是独立演示服务，不能代表目标系统。

处理：把“取得正式前后端接入点、身份/资源授权契约、受保护接口清单”设为生产接入前置条件；形成最小联调接口与负向用例：绕开 SDK 直接调用、签发失败、权限撤销、租户切换、导出。R-16 未完成前只能发布 SDK/实验结论，不能宣称业务系统已受保护。

### F-03 暗图块可复制，现有证据规则需覆盖明暗码冲突

`WATERMARK_RESEARCH_PLAN.md` 明确图块交给浏览器。服务端密钥保密可以防止从密钥生成任意图块，但不能阻止访问者复制已收到的图块并贴到别的图片，或覆盖、移除图块。若可见码指向 A、暗码指向 B，当前三态提取接口没有规定冲突如何呈现和调查。BCH 是纠错编码，不是加密；随机标识用于索引，SHA-256 文件散列用于完整性比对，都不能单独证明截图来源或阻止有效图块被移植。

处理：增加已知有效图块移植、拼接、重叠多租约、明暗码不一致的对抗样本；冲突时报告“证据不足/冲突”，保留全部候选和来源，不自动选择分数最高者。调查报告将“标识对应某次签发”和“图片来源/泄露责任”分栏，后者需独立证据。不能宣称客户端图块具有不可复制性。

### F-04 暗水印协议尚不足以跨版本实现和复核

候选仅给出 64 位暗码、BCH(127,64)、256×256 图块和透明度起点，缺少码字多项式/位序、同步序列、像素映射、DPR/缩放处理、颜色空间、图块相位、裁剪边界和版本解析。`T0` 的“固定向量完全符合”目前无法落成互操作测试；提取端也无法定义失败在何阶段。

处理：先冻结版本化二进制/像素协议和编码、绘制、截图、解码各阶段的固定向量；记录浏览器、DPR、缩放、主题和覆盖层状态。每个参数变更生成新算法版本并保留旧版提取器，旧记录可按版本核验。起始参数不得写成已达标配置。

### F-05 统计门槛与业务宣称需要再对齐

`BENCHMARK_PROTOCOL.md` 明确 200 张中 190 张算该格达标，也承认样本比例不保证总体成功率。190/200 的 Wilson 95% 下界约为 91%；10000 张负样本中 0 次误归属也不能证明误归属风险为零。当前矩阵对设备型号、客户端版本、图片尺寸分布和发布时间后的平台更新未规定最低覆盖，图片数量也可能由同一设备或场景重复贡献。

处理：在业务方确认“95% 是样本门槛还是期望总体下界”后冻结判定规则；按设备/客户端版本/页面内容/图像尺寸分层，记录独立采样单位和每层结果。增加明暗码冲突、图块移植、其他租户、低纹理/纯白页面和多候选负样本。平台客户端升级后触发再验证；报告支持范围及区间，不把一次封存集结论表述为永久保证。

### F-06 图片提取入口的资源与权限边界不完整

`API_CONTRACT.md` 只有 20 MiB 上传文件上限和格式列表。压缩文件大小不能限制解码后的像素、帧数、CPU、内存及并发占用；用户提供的 `caseId` 也必须对应真实案件且调查员有权操作。解码器处理不可信图片，是独立攻击面。

处理：在读取/解析前完成认证和案件权限；限制传输大小、实际文件签名、解码尺寸/总像素/帧数、运行时间、并发数和内存；隔离解码与提取工作进程，设置取消与超时。先计算原文件散列并保全只读原件，派生处理图单独记录；明确上传失败、审计失败和存储失败的状态码及保留策略。参考 OWASP File Upload Cheat Sheet。

### F-07 密钥生命周期、审计完整性和 SQLite 持久性尚未闭环

方案规定密钥不进前端或 Git，SQLite 事务提交后返回内容，但没有定义密钥生成、密钥 ID、轮换、旧版提取、吊销/泄露处理；也没有规定 SQLite journal/synchronous 配置、断电语义、RPO/RTO、WAL 管理和审计记录遭本机管理员篡改后的独立校验。进程重启测试不能替代断电、磁盘故障和恢复演练。

处理：记录每条租约的算法版本和密钥标识，密钥保管与轮换不改变历史查询语义；制定旧密钥受控保留/删除期限。明确 SQLite 持久性配置和故障测试，定期一致性备份与异地/独立日志保全，按约定 RPO/RTO 演练恢复。SQLite 可继续用于单机阶段，实际生产拓扑与审计可信度需单独验收。参考 SQLite 官方 PRAGMA、WAL 和 OWASP Logging 指南。

## P1：实施前补足验收细节

### F-08 页面状态与水印租约的一致性

方案提出短时租约和路由/用户更新，但未定义内容已显示而 SDK 绘制失败、刷新超时、旧请求晚到、新旧租约交替、标签页休眠后过期、Teleport 弹窗/全屏未覆盖时的统一处理。现有 S1 API 测试没有浏览器级截图断言；`WatermarkOverlay.vue` 也还没有完整 SDK 接口。

处理：给每个受保护视图定义内容版本/租约版本与原子呈现条件；在所有异常路径清空或遮蔽高敏感内容，由服务端继续执行门禁。用真实浏览器固定截图检查数据区域、弹窗、滚动、缩放、打印及过期瞬间，明确可见码和暗码分别达标的最小截图范围。

### F-09 S1 演示与生产边界仍需技术性隔离

`apps/api/server.mjs` 的生产启动保护只在直接执行该文件时触发；导入 `createApiServer()` 的调用者不会触发这道检查。演示身份、内存审计和内存限流仍可被复用。当前仓库已标记 S1 未验收，尚无生产部署，因此这是预防性发现，不是已部署漏洞。

处理：生产构建和启动入口不得包含演示身份路由；实现生产服务时使用独立配置与启动校验，并设置自动化测试证明演示模式无法在生产配置中启用。审查真实身份系统的会话、CSRF、租户隔离和每请求授权；不要把演示 `Origin` 比较视为完整的生产安全方案。

## 2026-11-06 追加复核：全部列表页与裁剪实验

### F-10 全部列表路由的验收分母仍未知

ADR-014 将首版范围扩为全部列表页，但当前只有四张形态参考图，没有正式路由清单。既不能据四图推断页面总数，也不能让算法矩阵只在最容易的模拟页通过后声明“全部列表页”。

处理：生产接入前冻结列表路由清单、页面负责人、数据分级、表格/弹窗/导出特征和例外清单。每个路由至少完成 SDK 生命周期、可见码覆盖、原图暗码与典型局部截图回归；T3/T4 按页面形态和高风险路由预登记抽样配额，单一路由失败不得被总体平均数掩盖。无源码或正式接入点时，R-16 继续未完成。

### F-11 裁剪档只有面积边界，尚不能定义可宣称的最小截图

C1–C4 按面积比例分档是有用的第一步，但同一面积下，宽高、长宽比、取样位置、页面纹理和保留的完整图块可差异很大。每档 200 张若主要来自规则矩形或少数页面，可能误判窄条/单行也可靠。

处理：在首轮试验前为每档预登记最小宽高、长宽比、边缘/中心/单行/弹窗/表格等位置及页面形态配额，原生区域截图与事后裁剪分别报告。发布时用“通过的像素范围＋形状＋页面形态＋平台版本”描述支持边界；低于边界或信息不足返回证据不足/未检出，绝不强行归属。样本门槛是实验目标，仍需实测。
## 建议的方案修订顺序

1. 先确定首批页面与内容出口，业务方选择导出/打印首版保护或禁用；取得真实系统正式接入点前，只推进 SDK 与虚构样本研究。
2. 固定暗水印协议、密钥版本和失败结果语义，再实现 T0；同时补齐图片上传边界与存储持久性配置。
3. 完成 SQLite 重启/断电/恢复及 T1 原图闭环后，执行对抗负样本和真实 A→B→C 矩阵；按业务支持范围判定，不通过则保持“未验证”。
4. 最后进行真实业务全出口联调、权限与证据链审查、灰度和回滚演练。只有对应发布门槛通过，才能宣称系统已保护实际业务页面。
